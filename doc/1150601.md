# 2025-06-01 變更紀錄

## 1. login 回傳簡化

**檔案：** `app/routers/auth.py`

登入成功後 body 不再回傳使用者資料，只回傳 `{"success": true}`。
使用者資料改由前端登入後另外打 `GET /auth/me` 取得。

**原因：** 已有 `/auth/me` 端點，login body 附帶 user 資料是多餘的，職責拆開更清楚。

---

## 2. 認證機制統一為 httpOnly cookie

**檔案：** `app/auth.py`

`get_current_user` 改為 cookie 優先，僅保留 Bearer header fallback 供 Swagger UI 鎖頭使用。
移除 `oauth2_scheme` 對一般 API 請求的影響，正式使用只走 httpOnly cookie。

`app/routers/auth.py` 保留 `POST /auth/token`（`include_in_schema=False`），
專門給 Swagger UI 右上角鎖頭登入使用，不對外公開。

---

## 3. 全域 Exception Handler

**檔案：** `main.py`

新增三個全域 exception handler，統一所有錯誤回傳格式為：

```json
{
  "success": false,
  "error": {
    "code": "錯誤代碼",
    "message": "錯誤訊息"
  }
}
```

| Handler | 觸發情境 | code |
|---|---|---|
| `HTTPException` | 401、403、404 等手動拋出的 HTTP 錯誤 | `HTTP_ERROR` |
| `RequestValidationError` | 422 請求欄位格式錯誤 | `VALIDATION_ERROR` |
| `Exception` | 未預期的 500 server error | `INTERNAL_ERROR` |

> 注意：502 由 nginx / 反向代理層產生，FastAPI 無法攔截，需在 nginx 層另行處理。

---

## 4. 新增 SuccessResponse schema

**檔案：** `app/schemas/common.py`、`app/schemas/__init__.py`

新增 `SuccessResponse` schema，用於只需回傳成功狀態的端點：

```python
class SuccessResponse(BaseModel):
    success: bool = True
```

---

## 5. login / logout 套用 response_model

**檔案：** `app/routers/auth.py`

`POST /auth/login` 與 `POST /auth/logout` 加上 `response_model=SuccessResponse`，
Swagger UI 的 Successful Response 改為正確顯示：

```json
{
  "success": true
}
```

logout 同步將回傳從 `ok({"message": "已登出"})` 改為 `{"success": True}`，與 schema 一致。
